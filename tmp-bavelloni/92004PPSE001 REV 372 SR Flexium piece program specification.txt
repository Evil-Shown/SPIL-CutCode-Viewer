2.2 STRUCTURE OF THE PROGRAM 
 
The post-processor must generate a text file countering a number of piece programs equal 
to the number of different schemes to cut.   
A progressive number (e.g. %3 ) identifies each pro gram in the first line. The number of 
the piece program must be between 0 and 3000  (0<Pr ogram number<3000). Once the 
value of 2999 is reached, the counter starts from one. 
 
Each piece program is made up of: 
• A heading containing geometrical information on th e sheet, the number of sheets to 
cut, the ones already cut etc.  
• A call to carry out cuts followed by an upgrading of the counter for glass sheets 
already cut.  
• The list of all cuts to carry out

3.1.3.3 Shape geometry 
 
Each different shape in the cutting scheme is written only once in the piece program.   
Each shape is contained between two labels starting from N10. 
So, the first shape will be described between label s N10-N11, the second between N12-
N13, the third between N14-N15 and so on. 
In this example only one shape is present (repeated  4 times) therefore, only labels N10 
and N11 are used.  
The general rule is: 
Last label used for the shapes =  (Number of Different Shapes * 2) + 10 - 1 
 
Call (**) G77N12N14  depends on the number of shapes in the scheme     
  G77NE1NE2 E1=First free label  = (Number of Diffe rent Shapes * 2) + 10 
  E2=E1+2

• Scheme of shaped cut G77N12N14

• Cutting scheme with two different shapes G77N14N16

N12-N13 Description of shape 2

define the acceleration value to use.

3.2  LOW-E Glass 
 
3.2.1 Introduction 
 
 
It’s possible identify two kind of LOW-E process: COMPLETE and PARTIAL. 
In case of a complete process, the result we gain i s a LOW-E path that coincides with 
the CUTTING one. Otherwise with the partial process  the LOW-E tool makes us 
minimize the geometrical elements that must be work ed. In this case it’s important to 
recognize the elements that we don’t need to work. 
 
Below it shows two pictures. On the left side is de scribed the COMPLETE LOW-E 
process, where the red straight lines are paths on which CUTTING and LOW-E process 
has to be performed. On the right side is described the PARTIAL LOW-E process where 
the straight green lines defines the cutting paths,  while the red ones indicates the 
CUTTING and LOW-E (minimized) paths. 
 
 
                 
COMPLETE       PARTIAL 
 
 
As we can see the in PARTIAL case the LOW-E process  is performed only on the shape 
edges. Only if the entire job was composed by strai ght-cut shapes the partial and the 
complete cases would be identical.

As described in § 
2.1.2 the operator can chose the reference used to execut e the cutting 
code. Four possible reference system are available,  for all of them the ISO code is the

correctly the rotation/translations related to the chosen reference.

3.6 Sending the cutting program to the Numerical co ntrol  
 
The piece program is loaded to the Numerical Contro l using a Glaston application – 
INOUTCNC - that transfer the ISO program from PC to CNC. 
 
From any application is possible to call INOUTCNC p assing file name to transfer to CNC : 
INOUTCNC will start the transfer of the ISO program  and, at the end of the operation, will 
show a message about the result. 
 
Next rows show an example to call INOUTCNC application ( using Visual Basic IDE ) : 
 
Dim RetVal as double 
 
Const InOutExe$ ="C:\EASYCAD\INOUTCNC\INOUTCNC.EXE" 
const NamefileIso$ = "C:\EASYCAD\PIPPO.CUT" 
 
RetVal = Shell(InOutExe$ + chr(32) + NameFileIso$) 
 
 
Shell function runs an executable program and retur ns a Variant (Double) representing the 
program's task ID if successful, otherwise it returns zero.

3.7 Displaying a cutting pattern preview  
 
The ISO code generator creates a JPEG picture file which contains the preview of the job 
pattern just elaborated. 
The CNC application seeks these files into a specific folder in order to preview the job:  
“ C:\$App_Path\Bin\IsoJpg ” 
where usually “$App_Path” correspond to “EASYCNC”, the standard installation folder. 
The file name corresponds to the name labeled into the ISO code description of the job.  
As an example, the picture file “ RUN0101_0001.gif ” is linked to the ISO code 101.cut 
where inside it we can read the line: 
%144 
N1( 
RUN0101_0001 ) 
N2E30000=15000E30001=1500E30002=0004 
… 
In case of a laminated glass, the application will create 2 JPEG files: one for the front and 
the other for the back. Again, as example, we’ll ha ve “ RUN0100_0001.gif ” and 
“RUN0100_0002.gif ”. The extension 0001 indicates the front, while 0002 the back. These 
files are linked to one cut file (100.cut). Inside it we can see: 
%142   FRONT ISO CODE 
N1( 
RUN0100_0001 ) 
… 
%143   BACK ISO CODE 
N1( 
RUN0100_0002 ) 
… 
NOTE : The way in which the preview is handled in EasyCN C may vary according to the 
selected ISO code generator (Optimizer)
